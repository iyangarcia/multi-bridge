# Evaluation set and calibration (phase 9)

*Generated 2026-10-24 by `scripts/calibrate.py`. Synthetic data only (C1).*

Files are generated by `evalset/` from invented records: patients for `cdss_paciente` (clinical pack) as CSV, Excel, JSON, XML, HL7 v2 and FHIR, and order lines for `pedido_json` (no pack) as CSV, Excel, JSON and XML. Each file is messy in its own way (header languages and codes, section prefixes, title lines, encodings, separators, date shapes, sex codes, units, decimal commas, capitals, split or combined names, lost leading zeros, missing fields, distractor columns), and its correct output is known.

A field is graded by its **output values**, not by its column name: the proposal is run on every row and compared with the correct values. **right**: every value right (or "no data" where the file has none). **pending**: left for a human. **missed**: "no data" where the file has it (incomplete, nothing false). **wrong**: some value wrong or invented; *silent* when the wrong value passes every rule of the destination (otherwise the engine sets those rows aside with the reason). **oracle**: the true columns with the transforms the rules choose for them, to tell column mistakes from transform mistakes.

**Calibration**: for every field the proposal gave a column (mapped, or pending with a column), was accepting it as proposed right? Counted per score band on the *fit* set, made non-decreasing with the score, then checked on the *held-out* set. The expected calibration error (ECE) is the average gap between the calibrated rate and what happened on the held-out files.

## Limits

- The files are as messy as the generator makes them. Real exports will have problems it does not draw, so the rates are a ceiling measured on known kinds of mess, not a promise for a new hospital. The web app says "en pruebas sintéticas" next to them for that reason.
- The matcher was fixed while building this set (seeds 0–299); the fit and held-out sets use other seeds, but the same generator, so they share its blind spots.
- A band with few proposals has a wide interval; the web app shows how many proposals each rate rests on.
- Only the bands are calibrated: the raw score still orders the review (recipe `confidence_kind`).
